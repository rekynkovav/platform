Ты — Primary Agent OpenCode. Задействуй ВСЕХ доступных саб-агентов (explore, general, а также специализированных из autopilot, если установлен).

Мой проект: 
- 17 модулей
- Реальное время: чаты + трансляции
- Шифрование (какое именно? уточни сам, посмотрев код)
- Постоянная память: PostgreSQL
- Кеш: Redis
- Облачное хранилище: Яндекс.Облако

Задача: найти ВСЕ потенциальные проблемы в коде. Ничего не редактируй без спроса, только анализируй и выдавай отчёт.

Чек-лист обязательных проверок (категория → что искать):

1. ШИФРОВАНИЕ:
   - Где хранятся ключи? (не должен быть в коде или env-файлах без защиты)
   - Используется ли постоянный IV/nonce для одного ключа? (должен быть случайным и уникальным)
   - Есть ли проверка целостности? (HMAC, GCM, а не просто CBC/CTR)
   - Передаются ли ключи по сети? (никогда)
   - Логируются ли ключи или расшифрованные данные? (никогда)

2. ПОСТГРЕС (память):
   - Инъекции: везде ли параметризованные запросы? (никакой конкатенации строк)
   - Транзакции: где нужны BEGIN/COMMIT? Не теряются ли COMMIT при исключениях?
   - Connection pool: не исчерпывается? Нет утечек соединений?
   - Индексы: есть ли медленные запросы без индексов? (запросы с LIKE %...%, OR, JOIN без условий)
   - Миграции: идемпотентны? Откатываемы?

3. РЕДИС (кеш):
   - Инвалидация кеша: где и как? Нет ли гонок (cache stampede)?
   - TTL везде проставлен? Нет вечных ключей, которые превратят Redis в свалку?
   - Паттерн "big key" (один ключ > 1MB)? Разбить.
   - Используется ли Redis как очередь? Тогда проверь ACK, dead letter, retries.

4. ЯНДЕКС.ОБЛАКО:
   - Ключи доступа: где хранятся? (IAM-роли лучше статических ключей)
   - Нет ли публичного доступа к бакетам?
   - Шифрование на стороне клиента или только на стороне облака?
   - Обработка ошибок: 429 (rate limit), 403 (доступ), 500 (облако упало) — не падает ли весь сервис?

5. ЧАТЫ (реалтайм):
   - WebSocket / SSE: обработано ли переподключение? Нет ли утечек слушателей?
   - Очерёдность сообщений: гарантирован ли порядок? Используется ли sequence number?
   - Нет ли дублирования при ретраях?
   - Не хранятся ли сообщения вечно в памяти сервера? (должны уходить в БД/Redis сразу или по таймеру)

6. ТРАНСЛЯЦИИ (стриминг):
   - Буферизация: не ест ли всю память при медленном клиенте?
   - Лимиты: есть ли на размер одного сообщения/кадр?
   - Разрыв соединения: корректно ли закрываются ресурсы?

7. МОДУЛИ (17 штук):
   - Циркулярные зависимости? (модуль А импортирует Б, Б импортирует А)
   - Обработка ошибок на границах модулей: где panic/fatal, где graceful degradation?
   - Есть ли dead code? (экспортируемые функции, которые никто не вызывает)

8. ГОНКИ И АСИНХРОННОСТЬ:
   - Где есть shared state без мьютексов/atomic? (особенно в горутинах, если Go)
   - Закрываются ли каналы/потоки?
   - Нет ли deadlock'ов? (взаимные блокировки)

9. ПРОИЗВОДИТЕЛЬНОСТЬ:/
   - N+1 запросов к БД (цикл с запросом вместо JOIN)
   - Сериализация/десериализация JSON/Protobuf в горячих путях
   - Блокирующие операции в event loop (если Node.js/Python asyncio)

10. БЕЗОПАСНОСТЬ (дополнительно):
    - JWT: проверяется ли подпись? Не доверяется ли алгоритм "none"?
    - Rate limiting: есть ли на эндпоинтах? (особенно регистрация, отправка сообщений)
    - CORS: разрешены ли только доверенные домены?
    - Загрузка файлов: проверка MIME-типа, лимит размера, сканирование?

Формат ответа:
1. Сводка: сколько проблем, критичность (CRITICAL/HIGH/MEDIUM/LOW)
2. По каждой категории (1-10) — найденные проблемы с конкретными файлами и строками (если можешь определить)
3. Если не можешь найти файл/строку — укажи, какие файлы нужно проверить руками
4. В конце — ТОП-3 проблемы, которые надо исправить в первую очередь

Никаких "в целом всё хорошо". Если ничего не нашёл — напиши "ничего не нашёл" и объясни, на основании каких проверок.
